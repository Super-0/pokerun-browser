## Deterministic native reproduction

In Chromium with the opt-in test-hook WASM build, `npm run test:native:schedule` exercised the real command queue and native reply collector. With the same synthetic delivery and DS timestamps, polling before send or while the command was in flight produced an empty poll. Polling after enqueue matched the reply. At fixed late ordering, a 32 µs timestamp deficit matched and a 33 µs deficit was stale. This reproduces both mechanisms independently of ROMs, browser timers and live Wi-Fi.

## Deferred poll experiment

The opt-in `POKERUN_DEFER_HOST_POLL=1 npm run test:white2` trial added a 32 ms emulated delivery window ahead of host TX completion. The reply collector still used the original emulated timestamp and existing stale rule. At 59.97/59.98 DS frames/s before greeting, native association occurred and every first poll followed browser command send and peer arrival. The host matched 415 of 454 polls, with 39 empty polls, five stale dispositions, and 39 failed-client ACKs. The host reported that the peer did not reply while the peer displayed “Hello!” Neither reached Trade. The trace was complete and is under `local-test-assets/white2-run-bvZa1G/`.

The adaptive `POKERUN_DEFER_HOST_POLL=adaptive npm run test:white2` trial used the same saved checkpoints. Both DS instances sustained about 60 frames/s. Native association occurred, then the host displayed “did not reply” while the peer displayed “Hello.” All 503 replies arrived, queued, matched, finished hardware RX as normal MP data, entered the RX ring, and were retired by host cursor advances. The peer likewise committed and retired all 503 ACKs. The native ACKs reported no failed clients, but the host command counter was zero for every ACK. The loss-free trace is under `local-test-assets/white2-run-STl9hV/`. This rules out an empty host reply queue, default replies and missing peer ACKs in that capture. It does not establish that the game accepted the response contents.

PRK81I at `5815918` shows a dedicated worker can service cross-tab callbacks with shared memory while separate WASM workers boot and render ROM frames. Its probe exchanges controlled packets between game frame runs. It provides a path to avoid advancing emulated time while waiting for a browser reply, but the probe itself does not exercise the Union Room.

The `POKERUN_DEFER_HOST_POLL=preserve-counter npm run test:white2` trial held the command countdown only during the added adaptive wait. Both emulators stayed near 60 frames/s. All 520 replies matched and reached the host software cursor; the peer retired all 520 ACKs. None had an expired command counter. The host still reported that the peer did not reply. This rules out counter expiry as a sufficient explanation. The loss-free trace is under `local-test-assets/white2-run-oXVMdn/`.

## Worker-synchronized radio

The opt-in worker patch runs each DS frame in a pthread and wakes the existing browser relay when native MP commands, replies or ACKs are queued. The host waits at its normal reply poll and the guest waits at the host-frame receive boundary after its reply. These are bounded wall-time waits with the DS clocks held. The standard transport path and ACK generation are retained.

The first frame scheduler waited for browser animation callbacks to notice completion. Both saved games booted but the pre-greeting rates fell to 46.53/45.66 DS frames/s, so the runner stopped before the invitation. With native completion notifications and deadline-based frame pacing, the next run sustained 59.90/59.90 before greeting and 59.99/59.99 during the attempt. Both games greeted, the host reached the Trade choice and sent an offer, and the guest reached the accept prompt. The 45-second greeting-only budget expired while stepping through the offer. No exchange was claimed. The loss-free trace is under `local-test-assets/white2-run-7dexH9/`.

The guest reported 5,111 successful firmware ACK indications and zero errors before ring arrival. Each ACK reached the guest ring 824 DS µs after its reply, with a 0.51 ms median wall delay. The host GFL receiver accepted seven guest data packets and called the guest negotiation handler twice. This is direct game acceptance evidence beyond the hardware match counts.

A later run completed the reciprocal exchange and returned to the trade screen. Both post-trade party summaries independently showed the Pokémon named in the opposite player's confirmation prompt. At 60.13/60.13 DS frames/s before greeting and 59.99/60.00 during the attempt, the host matched all 14,590 replies and reported no failed-client ACKs. The game outcome was `trade-confirmed`. The runner flagged incomplete timing because the guest's full trace could not be exported. The private confirmation and post-trade party captures are under `local-test-assets/white2-run-ref8p4/`.

The repeat passed end to end with `POKERUN_WORKER_RADIO=1 POKERUN_TRACE_GAME_NEGOTIATION=1 POKERUN_EXPECT_WHITE2=trade-confirmed npm run test:white2`. Both parties independently showed the expected incoming Pokémon after the exchange. The private driver automated the invitation and final trade selections. The final party summaries were checked through the same Playwright session because the offered party slot can differ between runs. The runner exited zero with no browser errors and both timing traces complete. Both games sustained 60.00 DS frames/s during the attempt. The host matched all 15,836 replies in the gameplay measurement, with zero failed-client ACKs. The full paired trace recorded 15,840 guest firmware ACK successes and zero earlier SDK ACK errors. The median guest reply-to-ACK ring interval was 824 DS µs and 0.54 ms wall time. The exact confirmation screens, post-trade party summaries and timing are under `local-test-assets/white2-run-KuLAWv/`.

The first confirmed trade and the first complete paired trace are archived privately in `local-test-assets/white2-trade-baseline-143a81f/` with a checked SHA-256 manifest. The local `white2-worker-first-trade` tag pins the verified worker implementation at `143a81f`.

## Fresh-session trade regression

The first batch stopped twice before the invitation when the archived live RAM probe could not verify one starting party. The replacement verifies the persisted party block against the latest valid White 2 checksum table and decodes each member from a copy. It preserves both backup regions and only reads the disposable IndexedDB batteries. The two initial failures are recorded in `local-test-assets/white2-streak-PabWdo/`.

Reopening the two batteries from the successful `KuLAWv` profile and comparing against the starting checkpoint independently verified that the reciprocal party exchange was persisted. The first unattended run with the new check passed, with complete paired traces and 59.90/60.01 DS frames/s during gameplay. Both batteries changed and passed footer, party block and member checksum validation. The trace contains 10,531 guest firmware ACK successes and one error before a subsequent ring commit. The game recovered and the trade persisted. See `local-test-assets/white2-run-fE55b1/` and the batch ledger in `local-test-assets/white2-streak-2Hk7r3/`.

The complete fresh-session batch ended with ten consecutive unattended passes. It completed 15 genuine trades across 16 sessions. Session six stopped at the extra C-Gear confirmation before any invitation. After the driver recognized that prompt, the last ten sessions all passed with both persisted exchanges and both complete timing traces. Gameplay health across those ten was 59.96–60.01 DS frames/s. A read-only audit of the first four completed profiles found two distinct exchange pairs. The final private ledger is `local-test-assets/white2-streak-2Hk7r3/result.json`.

## Normal-interface local wireless

The default-off `VITE_POKERUN_WHITE2_LOCAL_MULTIPLAYER=1` feature gives a real local room distinct firmware roles, uses the existing worker transport, and keeps the older injected actor code out of the local radio session. It pairs two tabs in one browser profile. The standard save selection and persistence paths stay in use. The legacy diagnostic launcher remains available.

The first normal-interface run passed with `POKERUN_WHITE2_NORMAL_UI=1`. It used the normal lobby, distinct saved slots, Ready and Start Game, and **Connect Local Wireless** on both tabs. The reciprocal exchange was verified from both persisted parties. Both emulators held 60.00 DS frames/s during gameplay and both timing traces were complete, with 10,324 guest firmware ACK successes and zero SDK ACK errors before ring arrival. The evidence is under `local-test-assets/white2-run-W5GkAK/`.
